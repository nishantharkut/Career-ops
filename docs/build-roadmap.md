# CareerOps Build Roadmap

Status: AI-first planning guide for goal mode.

This is not an implementation plan. It defines the correct build order so the e2e platform becomes useful without becoming unreliable.

The corrected direction is AI-assisted CareerOps with deterministic verification. The current deterministic Application Desk is a verifier foundation, not the final product.

## Phase 0. Repository And Test Harness

Goal: make the project safe to change.

Deliverables:

- git repository
- project structure
- dependency management
- test runner
- lint and format commands
- local config pattern
- hosted config pattern
- private data ignored by git
- initial smoke test

Exit gate:

- tests run locally
- private data paths are ignored
- docs remain in the repo

## Phase 1. Core Data System

Goal: store applications, resumes, evidence, reports, approvals, and audit events.

Deliverables:

- SQLite database
- migrations
- Pydantic models
- repository layer
- application state transitions
- audit event writing
- backup and restore command

Exit gate:

- application state tests pass
- approval invalidation tests pass
- backup and restore test passes

## Phase 2. Application Desk UI

Goal: make the day-1 workflow usable.

Deliverables:

- local React UI
- same-origin hosted UI/API mode
- application list
- application detail
- JD editor
- resume selector
- report panel
- approval panel
- plain operational copy

Exit gate:

- Playwright can create an application
- UI responsive checks pass
- no complex or AI-slop UI patterns

## Phase 3. Resume Render And Parse

Goal: connect LaTeX source to fresh PDF and parseable text.

Deliverables:

- LaTeX compiler adapter
- PDF checksum
- page count
- PDF text extraction
- stale PDF detection
- render log display

Exit gate:

- stale PDF fixture blocks approval
- fresh render passes
- broken LaTeX shows useful error

## Phase 4. Deterministic Verifier And Baseline Reports

Goal: produce trustworthy baseline reports and approval blockers without fake proprietary scoring.

Deliverables:

- deterministic JD parser
- resume parser integration
- exact keyword report
- requirement coverage report
- evidence risk report
- blocker and warning system

Exit gate:

- invented metric fixture blocks approval
- NDA wording fixture blocks approval
- unsupported title fixture blocks approval
- report links to exact JD and resume version
- UI labels baseline output as verifier output, not full AI analysis

## Phase 5. Evidence Vault And Repository Inspection

Goal: verify claims before they enter resumes.

Deliverables:

- evidence records
- claim records
- privacy levels
- repository inspection workflow
- branch and artifact notes
- metric verification status

Exit gate:

- unverified metric cannot be marked verified
- private evidence cannot leak into public text
- inspected repository evidence can support a claim

## Phase 6. AI Task Framework

Goal: add the durable task, artifact, provider, and provenance layer that AI needs before any model is trusted.

Deliverables:

- AI provider config model
- AI task model
- AI artifact model
- prompt-template versioning
- mock AI provider for tests
- schema validation
- privacy-mode tracking
- deterministic verifier after every AI task
- asynchronous task status in API and UI

Exit gate:

- AI tasks can be created, completed, failed, and retried without corrupting applications
- every AI output has provider, model, prompt version, privacy mode, checksum, and schema version
- cloud AI remains disabled unless explicitly configured and approved
- unsupported claims generated by AI are blocked by deterministic gates

## Phase 7. Local OSS AI Provider And AI Review

Goal: make the application desk genuinely useful with private local AI.

Deliverables:

- local provider adapter for Ollama first
- later OpenAI-compatible adapter that can support LM Studio
- bounded context-packet builder
- JD AI analysis
- semantic fit analysis
- resume-tailoring suggestions
- non-AI-slop copy review
- draft-only resume edits
- provider-unavailable fallback state

Exit gate:

- app can run `Run AI review` against a sample JD and resume using a mock provider in CI
- live local provider tests are opt-in
- private resume/profile text stays local in local private mode
- deterministic verifier blocks unsafe AI suggestions
- local score never claims to be Resume Worded or employer ATS

## Phase 8. Codex Deep Review

Goal: use Codex only for explicit deep-work tasks that need repository or session reasoning.

Deliverables:

- controlled task folder under `vault/ai-tasks/`
- Codex worker adapter
- allowed-source list per task
- output schema contract
- repository inspection task
- context reconstruction task
- evidence memo artifact

Exit gate:

- Codex worker cannot silently modify resumes or applications
- `.codex` sessions are read only when a task explicitly names allowed files
- multi-gigabyte sessions are parsed incrementally
- Codex output is stored as an artifact and rechecked by the verifier

## Phase 9. Cloud Watcher

Goal: discover public opportunities without touching private data.

Deliverables:

- separate watcher service
- allowed source list
- public job metadata only
- notifications
- import-to-local workflow

Exit gate:

- watcher has no access to profile, resumes, evidence, or reports
- watcher output can be reviewed before importing

## Phase 10. Hosting And Hardening

Goal: make the AI-assisted platform reliable for daily use at low or no recurring cost.

Deliverables:

- e2e tests
- visual checks
- artifact integrity checks
- secret scanning
- crash recovery
- hosted private deployment with auth
- persistent-volume deployment path
- `/health` endpoint and container health check
- restart policy for VM/container hosting
- backup and restore flow for SQLite plus vault files
- resumable AI tasks
- clear local-vs-hosted AI mode labels
- documentation refresh

Exit gate:

- day-1 workflow passes
- full local application packet test passes
- hosted mode serves the UI and API from one origin
- hosted mode requires auth for private routes
- hosted mode uses persistent `data/` and `vault/` storage
- hosted mode does not depend on hidden paid AI APIs
- local private AI mode remains available without cloud AI
- UI checks pass on required widths
- all known historical failure fixtures pass

## Build Principle

Every phase must leave the product usable. Do not add a new subsystem if the previous packet workflow is broken.
